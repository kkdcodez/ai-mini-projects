# 002. 모델 실험 및 오류 분석

**프로젝트:** 공유자전거 대여 수요 예측 (회귀)  
**작성 범위:** CP-04~CP-08  
**근거:** `code/01_regression_bike_demand_completion.ipynb`의 실행 결과

> **작성 예시:** 이 문서는 **비교 결과(수치) → 오류에서 발견한 점(관찰) → 해석**을 기록합니다. 최종 모델을 **왜 선택했는지**는 `adr.md`에 간결하게 남깁니다.

## 1. 모델 평가 기준 (CP-04)

- **주 평가 지표:** MAE
- **보조 지표:** RMSE, R²
- **모델 비교에 사용한 데이터:** **Validation** (Train으로 학습한 모델의 설정을 비교; Test는 최종 선택 이후 한 번 평가)
- **MAE를 주요 지표로 선택한 이유:** 시간당 대여량의 예측이 실제값에서 평균적으로 **몇 대** 벗어났는지 직접 해석할 수 있다. RMSE로 큰 오류를 보조 점검하고, R²로 설명력을 확인했다.

## 2. 모델별 실험 결과 (CP-04~CP-06)

동일한 Train·Validation 분할에서 비교한 결과다. **낮은 MAE가 더 좋은 성능**을 의미한다.

| 모델·설정 | Train MAE | Validation MAE |
|---|---:|---:|
| DummyRegressor (`mean`) | 119.572 | 194.109 |
| LinearRegression | 55.382 | 99.725 |
| DecisionTree (`max_depth=3`) | 81.203 | 134.941 |
| DecisionTree (`max_depth=6`) | 61.458 | 106.262 |
| DecisionTree (`max_depth=12`) | 32.966 | 79.959 |
| RandomForest A (`n_estimators=50`, `max_depth=10`) | 38.223 | 76.379 |
| **RandomForest B (`n_estimators=100`, `max_depth=15`)** | **22.255** | **64.517** |

**실험에서 발견한 점**

- **Decision Tree 깊이 변화에 따른 성능:** 깊이를 3 → 6 → 12로 늘릴수록 Validation MAE가 **134.941 → 106.262 → 79.959**로 낮아졌다. 실험한 세 설정 안에서는 깊이가 커질수록 검증 성능이 개선됐다.
- **Random Forest 두 설정의 차이:** B의 Validation MAE(**64.517**)가 A(**76.379**)보다 **11.862대** 낮았다. B의 Validation RMSE **91.353**, R² **0.832**로, A(RMSE **101.489**, R² **0.793**)보다 양호했다.
- **Train·Validation 성능 차이에서 관찰한 현상:** B의 MAE 차이는 **42.262대**, A는 **38.155대**, Tree(12)는 **46.992대**였다. `01_regression_data_analysis.md`에서 확인한 집합 간 평균 수요 차이(Train **159.7**, Validation **281.0**)도 있으므로, 격차 전체를 과대적합 탓으로 단정할 수 없다.

## 3. 예측 오류 분석 (CP-07)

- **비교한 후보 모델 2개(실제 Notebook 오류 분석 기준):** **RandomForest B** / **DecisionTree (`max_depth=12`)**
  - **선정 기준 주의:** 전체 Validation MAE **1·2위는 RF-B와 RF-A**이지만, Notebook의 CP-07에서는 **RF-B와 단일 결정트리(Tree-12)**를 골라 서로 다른 모델 구조의 예측 오류를 비교했다.
- **실제값·예측값 그래프에서 관찰한 점:** 두 모델 모두 실제 대여량이 큰 구간에서 예측값이 기준선(`예측=실제`) 아래로 놓이는 경우가 나타나 **고수요 구간 과소예측** 경향이 보인다. 잔차(`실제−예측`) 평균은 RF-B **+3.6대**, Tree-12 **+6.8대**였다.
- **시간대별 MAE가 큰 구간:** RF-B 기준 **17시 120.3대**, **18시 112.7대**, **19시 97.2대**, **16시 85.5대**. 퇴근 피크의 절대 오차가 상대적으로 컸다.
- **모델이 상대적으로 잘 예측하지 못하는 상황:** 대여량이 매우 많은 시간대. 한편 새벽 4시는 실제 평균이 **9.5대**인데 RF-B MAE가 **50.7대**여서, **절대 오차만으로 모든 시간대의 예측 품질을 설명하기 어렵다**.
- **(선택) 특성 중요도에서 확인한 점:** RF-B의 Validation permutation importance(MAE 증가량)는 `is_commute_hour` **92.0**, `hr` **64.9**, `hum` **37.8**, `workingday` **24.0** 순이었다. `yr` 중요도가 **0.0**인 것은 Validation에서 `yr`이 모두 1이기 때문이므로 전체 데이터에서도 무의미하다는 뜻은 아니다.

**분석:** RF-B는 Tree-12보다 **24개 중 23개 시간대**에서 MAE가 낮았고, 잔차 표준편차도 **91.3대 vs 115.3대**로 작았다. 다만 **19시**에는 Tree-12의 MAE(**89.3대**)가 RF-B(**97.2대**)보다 낮았으며, 퇴근 피크의 높은 절대 오차는 RF-B를 선택해도 남는다.

## 4. 최종 모델과 Test 평가 (CP-08)

- **Test 확인 전에 선택한 최종 모델·설정:** `RandomForestRegressor(n_estimators=100, max_depth=15, random_state=42, n_jobs=-1)` (RF-B)
- **재학습에 사용한 데이터(Train + Validation) 크기:** **14,755행**, 입력 **12개 특성**
- **Test MAE:** **66.752대**
- **Test RMSE:** **96.100대**
- **Test R²:** **0.800**
- **모델 저장·재로딩 및 예측 결과:** 전처리와 모델을 포함한 Pipeline을 `results/01_final_model.joblib`로 저장(**약 8.7MB**) 후 다시 불러왔다. **Test 앞 100건에서 저장 전후 예측이 일치(`True`)**했으며, 예시 입력의 예측값은 **평일 18시 맑음 748대 / 03시 맑음 19대 / 18시 비 305대**였다.

**해석:** 최종 RF-B의 Test MAE는 **66.752대**, R²는 **0.800**으로 기록되었다. Train+Validation으로 **재학습한 뒤 별도의 Test 구간**에서 얻은 결과이므로, 이전 Validation 수치와 단순한 개선율로 해석하지 않고 최종 일반화 성능으로 보고한다.

> Test는 **최종 평가용**이다. 이 점수를 보고 하이퍼파라미터를 다시 선택하지 않는다.

## 5. 실험 요약

- **가장 중요한 실험 결과:** RF-B가 비교한 7개 설정 중 Validation MAE **64.517대**로 가장 낮았고, CP-07의 오류 비교에서도 Tree-12보다 **23개 시간대에서 낮은 MAE**를 보였다.
- **남아 있는 모델의 한계:** 고수요 시간대의 과소예측 및 17~19시의 높은 절대 오차, Train·Validation 간 수요 수준 변화가 남아 있다. 추가 개선 시 시간순 교차검증·피크 수요 관련 특성·하이퍼파라미터를 **새 검증 절차로** 점검할 수 있다.
